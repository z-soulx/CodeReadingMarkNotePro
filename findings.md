# Findings
- 3.7.8 release completed on 2026-09-15: Gradle/plugin descriptor/package versions match, 71 tests passed, and `publishPlugin` uploaded successfully with the configured Marketplace token. Signing was intentionally skipped because no certificate/private key is configured; Marketplace availability may still depend on JetBrains processing.
- 3.7.8 release scope: linked workspace project support (logical alias display, real-path identity/de-duplication/routing) plus data-driven child eligibility requiring `.idea/CodeReadingNote.xml`.
- 2026-09-15 follow-up requirement: a nested directory is a plugin note project only when `.idea/CodeReadingNote.xml` actually exists. Merely having `.idea` must no longer create an empty child project in the workspace tree. The currently opened workspace root remains present independently of this child eligibility rule.
- Implemented the eligibility check with `Files.isRegularFile(..., NOFOLLOW_LINKS)`: a missing path, directory, or linked notes file does not qualify. Linked project roots still work because only the final notes-file entry is checked without following; a symlink/junction in an ancestor remains supported.
- 2026-09-15 report: on macOS, projects exposed under a workspace through symbolic links (for example `aa1` and `aa2`) are not effective for workspace project notes sync. Root cause is not yet established; investigate discovery traversal and logical-vs-real path identity separately.
- `WorkspaceDiscovery` explicitly walks without following links, excludes linked `.idea` directories, and documents Windows junction exclusion. A workspace child that is itself a macOS symlink is therefore never traversed or discovered; this is a direct explanation for the report. A fix must define logical alias identity versus physical target identity and guard cycles/duplicate aliases.
- `NoteProjectContext.root` currently serves three roles: coordinator identity, XML storage location, and workspace-relative display. `WorkspaceNotesService.forFile` and open-project reuse also compare only lexical normalized paths. Merely enabling `FOLLOW_LINKS` would leave duplicate-alias writes and canonical VFS/open-project paths incorrect.
- Implemented contract: only links directly targeting a project root are admitted; arbitrary linked containers remain untraversed. Context/storage/sync identity uses the real path, while each workspace service maps that identity back to the first sorted logical alias for display. Physical and logical roots are both observed for VFS changes.
- Final call-chain review found note creation still used lexical IntelliJ VFS ancestry. Alias-backed files now derive project-relative paths through real filesystem identity so persisted XML remains portable instead of falling back to an absolute external URL.
- Publish prerequisite failure: current JAVA_HOME points to jdk1.7.0_80, with jdk-17 installed. IntelliJ Gradle 1.17 bytecode confirms signPlugin unconditionally depends on downloadZipSigner before onlyIf skips unsigned signing; removing only that edge when signing is unconfigured preserves explicit tool tasks.
- Issue #15 (public read): existing remote XML cannot be updated, deletion makes push succeed. Screenshot is HTTP 422 with truncated literal escapes. Legacy getFileSha reads default branch, returns null on arbitrary errors, while PUT uses configured branch. formatApiError uses a regex that truncates escaped quotes. New notes transport already has explicit ref/conditional SHA, but groups all 422 as conflict; improve distinctions and validate nonempty SHA. Screenshot alone does not establish the reporter's precise branch/configuration.
- Implementation verification: IntelliJ 2024.3 exposes StoreUtil.saveSettings(ComponentManager, boolean). Root sync uses platform save then verifies actual disk XML; child sync uses the shared serial XML writer. Project.getState alone is not used as persistence confirmation. New GitHub reads explicitly include branch ref (legacy contents reads did not).
- Source-verified sync follow-up: SyncService exports root topics without trash, rejects empty topics, and merges by name/time. GitHub notes path is basePath/projectIdentifier/CodeReadingNote.xml; identifier comes from IDEA project name. Provider accepts an explicit identifier, but fetches the latest SHA inside push instead of enforcing an observed baseline. The .md5 sidecar is a cache, not a safe conflict oracle. SyncStatusService persists only time/MD5; pause is runtime. Workspace coordinator has revisions and durable saves but needs explicit snapshot/save-completion APIs for sync.
- Follow-up request is a sync design: manually select child projects and keep them synchronized while only the parent workspace stays open. Existing 3.8.0 scope remains local-only; proposed behavior belongs in a new spec, not current-system docs.
- Root getTopicList/getState must stay root-only for sync.
- Models need runtime ownership; list events need context.
- Import setters emit events; loading must suppress changes.
- Compilation passed after correcting Disposable imports. Root serialization remains root-only. Added scoped native bookmark groups and runtime marker IDs; XML UIDs remain legacy-compatible.
- Shared-window/detail updates preserve focused editor documents when text is already current. VFS subscription uses the application bus, with project disposal ownership. Scanner and serial saves use separate queues. Recovery lives in IDEA config to avoid recreating deleted project directories.
