# GitHub Provider 差异页

`GitHubSyncProvider`（位于 `sync/github/`）是 `SyncProvider` 策略目前唯一的实现。
本页只写它区别于通用同步逻辑的部分，通用语义看 `README.md`。

## 错误解析（formatApiError）

GitHub 的报错不是纯 JSON，插件按响应内容自适应解析：

- **JSON 响应**：使用 Gson 解析 `message` 字段，完整解码换行和转义引号；输出前移除 Token，不用正则截取 JSON 字符串
- **HTML 响应**（如网关/限流页）：提取 `<title>`，并解码 HTML 实体
  （`&middot;`、`&mdash;` 等转回可读字符）
- **按 HTTP 状态码附加上手建议**：
  - `401` -> 检查 token
  - `404` -> 检查仓库是否存在/可访问
  - 其余常见状态码各有对应提示

目标：用户看到的报错永远是「发生了什么 + 该检查什么」，而不是原始报文。

## 路径编码

含非 ASCII 字符的文件路径按**路径段**逐段 URL 编码，避免整条路径一次性编码破坏 `/` 分隔。

## 交互约定

- token 与仓库地址存于应用级 `codeReadingNoteSync.xml`（跨项目复用）
- 3.7.7 笔记远端标识来自项目绑定，首次提供清洗后的旧项目名作为候选；布局仍为 `<basePath>/<id>/CodeReadingNote.xml`
- `GitHubNotesRemote` 的笔记读取显式使用配置分支 ref，返回 XML、blob SHA 和 ETag；304 复用缓存，404 另行核实分支是否可访问
- 笔记 PUT 传入此前读取并判定安全的 SHA；409/412 返回冲突，422 区分缺少 SHA、SHA 不匹配和其他校验错误，不重新取得最新 SHA 强行重推。创建使用无 SHA 的缺失前置条件
- `.md5` 继续更新以兼容旧客户端，但不作为权威数据或覆盖依据；校验缓存失败标记单独状态，下轮先读 XML 再修复缓存
- HTTP 错误以国际化状态显示，不把原始服务器正文或 Token 放入异常；403/429 尊重限流等待，仓库写入串行

> 本页基于 `.ai/ARCHITECTURE.md` 既有描述迁移；新增 API 行为时先改代码再回流本页。

## 已有文件更新（issue #15，3.7.7）

共享 `GitHubSyncProvider` 的 SHA、文件内容及 MD5 读取都指定配置分支 ref；提交时间查询也指定 sha 分支，避免读取默认分支后向另一分支写入。读取返回 401/403/服务错误或成功响应缺少 SHA 时抛出可操作错误，不再返回 null 当成文件不存在。只有文件 404 且确认配置分支可访问时，SHA 查询才返回缺失。

issue 截图中的 `Invalid request.\n\n\` 是旧 JSON 正则在转义引号处截断的表现，截图未包含完整服务器原因。修复后的共享 Provider 显示完整解码信息和中英文建议；工作空间通道仅暴露安全的分类状态。已有 XML 使用对应分支的有效 SHA 更新，用户无需先删除远端文件。模拟 HTTP 回归验证了非默认分支连续更新和读取失败不发 PUT。
