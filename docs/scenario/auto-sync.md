# 场景：自动同步（Auto Sync）

## 笔记通道（3.7.7）

`WorkspaceNotesSyncCoordinator` 在应用级共享串行队列；`AutoSyncScheduler` 和 `SyncStartupActivity` 仅将窗口接入该协调者。子项目不用创建额外 IDEA Project，也不需要单独打开或在树中展开。

每项目绑定保存自动策略：仅手动、自动推送、安全双向。应用级 enabled 是总开关；原 autoSync 选项是根项目首次绑定默认自动推送的偏好，已有绑定以其自身策略为准。新发现项目未绑定时不联网首推，用户可在工作空间同步面板勾选并批量设置策略。

| 触发 | 处理 |
|---|---|
| 窗口打开、发现新绑定 | 首次检查已加载的自动项目；无基线时等待手动对齐，双方内容相同可保存后建立基线 |
| 本地 revision 变化 | `NotesSyncSchedule` 按项目重置 3 秒防抖；实际推送前刷盘并验证 |
| 长期没有编辑 | 默认每 5 分钟检查远端，绑定可设置 1–60 分钟 |
| IDEA 激活 | 上次检查至少 60 秒之前才补充检查 |
| 离线或网络失败 | 每项目指数退避，最高 30 分钟；手动操作可主动重试 |
| GitHub 限流 | 尊重 Retry-After/限流重置，同一共享仓库队列等待 |
| 关闭窗口 | 释放窗口订阅；其他窗口仍引用项目则继续，否则停止其网络任务 |

读取使用 ETag，在 304 时复用远端快照，写入使用已经观察到的 SHA 条件。任务在项目之间让出队列，避免批量自动检查长期阻塞用户手动请求。

方向由上次确认一致的内容 B、本地 L、远端 R 决定：L=R 无需传输；仅 L 改变可推送；仅 R 改变且安全双向模式才自动拉取；双方不同修改暂停该项目。自动推送模式发现远端更新后等待用户处理。无基线、远端缺失、数据损坏均不得自动覆盖。

暂停和基线持久化在 IDEA 配置目录，重启不能绕过冲突。用户在同步面板查看项目路径、状态及时间；认证或配置修复后可手动检查或重新保存项目同步设置。冲突对比提供采用本地或远端，并保存替换前备份。拉取期间新增编辑、磁盘外部修改或绑定变化会拒绝旧结果。

## AI 配置通道

AI 配置仍使用独立 `AIConfigAutoSyncScheduler`：VFS 修改后 5 秒防抖，要求应用级 enabled、aiConfigAutoSync、配置校验通过且未暂停。还要求 `getLastSyncedRemoteMetadataHash()` 非空，没有手动同步历史时不做自动首推。该通道未扩展为工作空间子项目同步。

AI 部分仍保留既有实现行为，不能把笔记通道的新调度、错误状态或基线语义套用到 AI 通道。
