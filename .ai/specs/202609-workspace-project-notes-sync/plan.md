# Plan: 工作空间按项目同步笔记

- Unit: `202609-workspace-project-notes-sync`
- Status: proposed，本文描述待实现行为

## 1. 交互

项目节点右键增加“推送此项目 / 拉取此项目 / 检查更新 / 同步设置”。工具栏推拉根据树选中项解析项目归属，提示明确显示相对路径，例如“推送：dc-common”。点击时冻结目标；异步运行期间改变选择不会换目标。工作空间节点或没有项目选择时打开选择面板，不默认操作根项目。仅单项目时保留直接入口。

新增“工作空间同步”面板：项目相对路径、远端绑定、自动策略、状态、上次检查、上次成功同步。支持勾选项目执行推送、拉取或检查，并批量设置策略。选中项与批量范围始终可见；批量结果逐项呈现“成功 / 无变化 / 待处理冲突 / 失败”，可只重试失败项。项目树用图标表示待同步、远端更新、冲突、失败，详细原因在提示及面板中显示，运行时语言切换同时刷新。

日常操作无需重复确认；仅首次绑定、双方差异及明确覆盖操作展示差异和目标。冲突入口提供对比、备份本地后采用远端、备份远端后采用本地、稍后处理。自动模式不调用现有按主题名的合并；精细逐笔记三方合并留作后续功能。

## 2. 项目身份、绑定和配置

本地使用 `NoteProjectContext` 的规范化根路径；远端使用显式绑定，身份为 `(provider, repository, branch, basePath, remoteProjectId, notes channel)`，不上传本地绝对路径。现有布局保持 `<basePath>/<remoteProjectId>/CodeReadingNote.xml`，已有项目优先展示旧项目名清洗结果作为候选，不能只因同名就认定是同一个项目。

本地项目入口允许 workspace 下直接指向项目根的符号链接。除当前打开的根项目外，发现器只接受实际存在普通文件 `.idea/CodeReadingNote.xml` 的目录或链接目标；只有 `.idea` 不构成插件子项目，普通目录链接也不递归。协调器、同步状态和独立窗口复用使用 `toRealPath` 的磁盘身份，同一真实目录的多个 alias 去重；workspace 树和绑定候选仍使用发现时的逻辑 alias。文件归属同时识别 alias 路径与真实路径，避免 macOS VFS 规范化后落到父项目。

绑定面板列出远端目录，允许“使用已有目录”或“创建新目录”。同名子项目展示完整相对路径；新目录可建议 `业务名-项目名`，由绑定结果固定。校验目录段，拒绝空值、分隔符及 `..`。本机两份不同根目录绑定同一远端时明确提示，默认要求改名；确需同步同一逻辑项目可显式允许，但使用同一远端任务锁并分别保留本地基线。

建议每项目 `.idea/notesSyncBinding.xml` 保存无密钥的远端绑定和自动策略，使用独立 XML 适配器及应用级协调单一写入，可选纳入用户的项目版本控制；根窗口和独立子窗口读取同一份文件。绑定文件不是笔记同步载荷。凭据仍来自现有应用级设置，不复制 token。绑定的仓库与当前凭据配置不匹配时显示“配置已改变，需重新绑定”，不把旧基线用于新仓库。

基线、远端 SHA、最后检查、成功时间、暂停原因、恢复日志放在 IDEA 配置目录 `CodeReadingNote/notes-sync/` 下，按本地根路径及完整远端身份派生键，原子保存且不共享到远端。复制项目到新设备有绑定但无基线时走首次对齐。老 `syncStatus.xml` 的时间/MD5 只能辅助迁移展示，不足以授权自动覆盖；旧配置保留“自动推送”意图，先对齐基线再恢复。暂停在重启后仍生效。

## 3. 自动同步推荐

| 策略 | 本地保存后的行为 | 远端变化后的行为 |
|---|---|---|
| 仅手动 | 标记待同步 | 用户检查时显示更新 |
| 自动推送 | 3 秒防抖，核对远端后推送 | 后台检查后显示更新，暂停有风险的推送，用户手动拉取 |
| 安全双向（推荐显式批量启用） | 同上 | 本地相对基线未变时自动拉取；双方差异则暂停该项目 |

新发现项目默认仅手动；工作空间可“一次选中多个项目 → 安全双向”，未绑定项逐项完成绑定和首次对齐后才进入自动队列。未选择的项目及 AI 同步不受影响。应用级同步开关是总开关；旧 autoSync 迁移为已知根项目策略，后续笔记调度读取每项目策略，避免两个开关语义冲突。

触发点：工作空间发现并加载完成、新项目绑定完成、IDE 窗口重新激活（至少距上次检查 60 秒）、默认每 5 分钟轮询（可配置 1–60 分钟）。本地修改按所属项目保存成功后防抖，周期任务也处理离线期间积累的本地修改。仅自动策略参与定时网络任务，手动检查可检查全部选中项目。同步不依赖项目树是否展开。

调度在应用级按项目去重，同仓库写请求串行，读取并发最多 2；周期错峰，定时/激活/编辑事件合并。使用 ETag/远端 SHA 避免无变化时重复下载；支持按仓库查询未变化的 branch head 后跳过该轮，下一次仍按文件核实。403/429 尊重 Retry-After 与限流重置，网络失败指数退避至 30 分钟；401 等配置错误等待修复。错误在面板可见、通知去重，不每轮弹窗。

只要至少一个包含该项目的 IDEA 窗口保持打开，任务持续运行；关闭全部相关窗口后不做后台云同步。关闭时保证本地保存和恢复日志，取消网络排队，不等待网络完成；下次打开重新核对远端。

## 4. 以内容基线决定方向

维护上次已确认一致的内容摘要 B，以及本次本地 L、远端 R。摘要覆盖完整业务 XML（含回收站、顺序及未知扩展字段），仅规范化编码、属性顺序等不影响语义的差异，不排序主题或笔记，不使用更新时间大小判定胜负。远端 SHA 是写入前置条件，不替代内容比较；未知字段规范化规则必须有夹具验证。

| 条件 | 安全双向动作 |
|---|---|
| L = R | 不传输，确认基线与远端版本 |
| L ≠ B，R = B | 推送当前已保存快照 |
| L = B，R ≠ B | 拉取并保存远端快照 |
| L ≠ B，R ≠ B，L ≠ R | 该项目暂停并提示冲突，其他项目继续 |
| 无 B | 进入首次对齐；内容相同可直接建立基线，不同则手动决定 |
| 文件缺失、无法读取、XML 损坏 | 单独状态，不作为空数据或“没有变化”处理 |

“本地已刷盘”不等于“没有未同步修改”，必须比较 B。已有基线的合法空 XML 可同步删除全部主题/笔记；首次对齐的本地空载荷不得覆盖远端。远端 404 先区分仓库/分支不可访问与已知文件缺失，保留本地，等待明确恢复；不自动删远端文件。

## 5. 服务与数据流

新增应用级 `WorkspaceNotesSyncCoordinator`，消费 `WorkspaceNotesService.projects()`，复用 `WorkspaceNotesCoordinator` 模型与存储，绝不创建假的 IDEA Project。建议接口：

- `NotesSyncTarget(context, binding, configGeneration)` 固定运行目标。
- `NotesSyncDataSource.snapshot()` 返回完整 XML、业务摘要、模型 revision、磁盘基线。
- `flush(revision)` 返回真正持久化成功的 future；根通过平台保存完成信号，子项目通过串行存储适配器。调用 `getState()` 不能作为完成凭据。
- `applyRemote(snapshot, expectedRevision, expectedDiskBaseline)` 条件应用、发布所属项目事件并持久化；失败保留恢复副本。
- Provider 新增 `readNotesSnapshot(binding)` 与 `pushNotes(snapshot, expectedRemoteSha)`，读取返回 content、SHA、ETag 和明确的缺失/失败状态。旧接口仅做根项目兼容门面。

推送：保存成功 → 取得不可变本地快照 → 读取远端并判定 → 使用所观察的 SHA 条件写入 → 仅记录实际上传快照的基线。409/412 或更新冲突不重取最新 SHA 强行重试。上传期间有新编辑时保持待同步，排下一轮；结果不能用完成时最新内存内容计算“已同步”摘要。远端 XML 是权威，`.md5` 只是旧版缓存，不能决定是否安全覆盖；保留更新兼容 sidecar 的行为，失败可重试且显示状态，不把已成功 XML 写入当成未发生。

拉取：下载并验证完整 XML → 在共享模型变更线程重新核对 revision、磁盘基线、绑定代次和生命周期 → 保留本地恢复快照 → 应用所属列表（包括回收站）→ 等待持久化 → 提交基线。应用与编辑事件须串行，网络在后台。远端应用事件携带 REMOTE_APPLY 来源，避免触发原样回推。模型/磁盘冲突或项目移除使旧下载作废。保存失败不提交同步成功。

为应对本地应用成功但基线写入前崩溃，先写事务恢复记录（旧基线、目标快照摘要与 SHA、阶段）；重启核对磁盘与远端后完成或进入冲突。网络超时但服务端可能已写入时，下一轮先读远端；若 L = R 则确认，不能直接盲重推。

旧载荷没有 trash 时，保持已有导入兼容行为：保留本地回收站，再把结果当作本地差异，而非错误声明与远端完全一致。新版完整同步应显式序列化空 trash，表示有意清空；旧版读取忽略兼容节点。外层本地 `.idea` 组件或其他 XML 内容不作为笔记业务载荷上传，但必须原样保留在本地文件。

同一根目录多个窗口复用模型、绑定和同步状态；关闭一个窗口只释放订阅，有剩余窗口则选用有效窗口承载通知和导航。应用级远端身份锁避免重复推拉；跨 IDE 进程仍依靠磁盘基线检查及远端 SHA 条件写入防覆盖，不承诺跨进程实时共享内存。

## 6. 影响与约束

| 模块 | 改动 | 主要验证 |
|---|---|---|
| SyncService / Provider / GitHubSyncProvider | 根门面委托目标服务、内容快照、条件写入 | 原远端布局、SHA 并发、MD5 缓存非权威 |
| WorkspaceNotesCoordinator / CodeReadingNoteService | revision 快照、保存完成、条件应用 | 根/子存储、双窗口、关闭和异常恢复 |
| WorkspaceDiscovery / WorkspaceNotesService | 按笔记文件发现项目根/链接、真实路径去重、alias 显示和文件归属 | 无笔记文件目录、macOS symlink、Windows junction、重复 alias、普通目录链接不遍历 |
| AutoSyncScheduler / SyncStartupActivity | 委托应用级每项目队列，停止旧重复任务 | 不双推、不漏掉未编辑项目 |
| SyncStatusService / SyncStatusNotifier | 按目标路由，根 API 兼容 | 子项目状态不覆盖根状态 |
| SyncPushAction / SyncPullAction / ManagementPanel / TopicTreePanel | 显式选择及归属、总览和右键入口 | 焦点变化、批量部分失败 |
| TopicListExporter / Importer | 完整载荷及旧缺失字段语义 | 回收站、空数据、未知字段、顺序 |
| i18n / help / docs | 中英文及运行时切换、交付后回流 | 设计阶段不宣称功能已存在 |

约束已纳入方案：密钥不进载荷/日志；全 UI 国际化；旧 XML 可读；网络不在 EDT；所有订阅和任务可释放。功能发布建议 3.7.7，实施时同步修改 Gradle、plugin.xml 及变更说明，本次设计不修改 3.7.7 包。

## 7. 取舍

仅增加项目选择能解决手动推拉，但无法让长期未编辑项目收到更新，故补充后台远端检查。工作空间聚合成一个远端文件会破坏独立项目历史及数据归属，故保持逐项目文件。时间戳覆盖与按名自动合并难以处理删除、同名主题及设备时间偏差，故采用内容基线并在双方变化时交给用户。
