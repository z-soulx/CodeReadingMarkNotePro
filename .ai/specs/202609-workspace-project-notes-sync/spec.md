# Spec: 工作空间按项目同步笔记

- Unit: `202609-workspace-project-notes-sync`
- Status: verification（3.7.7 构建成功，71 项自动测试通过，含笔记文件资格与 Windows junction 回归；真实 IDEA/GitHub 与 macOS 安装验收未执行）
- Type: feature

## 意图

用户只打开父工作空间，也能指定任一子项目推送或拉取；长期不单独打开、甚至没有本地编辑的子项目，也能收到远端笔记更新。以每个项目为独立同步单元，工作空间负责选择、调度和展示。

## 背景

3.7.7 已提供工作空间本地读写，原变更单元为 `202609-multi-project-notes-workspace`。当前同步背景见 `docs/domain/sync/README.md`、`docs/scenario/auto-sync.md`。源码核实：现有工具栏以当前 IDEA Project 为目标，自动同步是本地修改后 3 秒防抖推送；远端标识来自项目名。现有笔记推送不携带回收站，空主题集合会被拒绝，按主题名与时间的合并不具备三方冲突判断能力。

## 范围

- 根项目和所有存在 `.idea/CodeReadingNote.xml` 的已发现子项目均可独立手动推拉、检查更新、设置自动策略；只有 `.idea` 而没有插件笔记文件的目录不算笔记子项目。
- 自动策略：仅手动、自动推送、安全双向。工作空间提供批量设置，实际策略跟随项目，不随树选中项改变。
- 延续应用级 GitHub 凭据与仓库配置；每个项目独立绑定远端目录、记录同步基线与冲突状态。
- 同步完整笔记集合：主题、分组、笔记、排序和回收站，保留现有 XML 格式及子项目相对代码路径。
- AI 配置同步、AI 工作台、代码 Git 推拉、未发现的任意远端项目批量导入不在本单元范围。

## 验收标准

- [ ] 在父窗口选中 dc-common 的项目、主题、分组或笔记后，推送/拉取均明确指向 dc-common，根与其他子项目数据及同步基线不变。
- [ ] 选中工作空间或没有选择时显示项目选择面板；支持多选、搜索、按状态筛选；一项失败不阻断其他项。
- [ ] 同名目录或名称清洗后同名的项目不能无提示共用远端目录；已有远端名称可显式绑定，父目录重命名不改变已绑定路径。
- [ ] 安全双向模式在工作空间打开及周期检查后获取远端单边变化，无需独立打开或编辑子项目；运行中检查间隔默认 5 分钟，可配置。
- [ ] 本地单变安全推送、远端单变安全拉取、双方不同变化暂停、双方已相同只更新基线；时间戳变化不能单独决定覆盖。
- [ ] 无绑定或无可信基线不自动首推/首拉；首次同步可选择拉取已有远端或初始化远端，双方有不同数据时必须先解决差异。
- [ ] 拉取下载期间发生本地编辑、磁盘外部修改、项目移除或绑定切换时，旧任务不得覆盖新数据或写错位置。
- [ ] 推送期间继续编辑时只把已上传快照记为基线，后续编辑仍待同步；远端并发修改必须通过 SHA 条件写入拒绝。
- [ ] 本地保存失败/冲突阻止该项目自动同步；离线、401、403/429、404、远端损坏各有独立状态和中英文提示。
- [ ] 空集合可以作为已确认同步项目的合法删除结果传播；远端文件缺失不视为空集合，也不自动重建远端或清空本地。
- [ ] 回收站、顺序、未知兼容字段在同步后保留；旧 XML 仍可读取，旧无回收站载荷不会被默认为清空本地回收站。
- [ ] 同 IDE 同时打开父工作空间和子项目时共享绑定、基线与任务，一个项目只产生一条同步任务链；关闭一个窗口不打断仍被其他窗口使用的项目。
- [ ] macOS/Linux 符号链接（以及 Windows junction）直接指向含 `.idea/CodeReadingNote.xml` 的项目时可被父工作空间发现、编辑和同步；界面显示 workspace 内 alias，相同真实目录的多个 alias 只加载一份模型/绑定/基线，普通源码目录链接不被递归扫描。
- [x] 子目录只有 `.idea` 而没有 `CodeReadingNote.xml` 时不显示为插件子项目；创建笔记文件后刷新可发现，删除笔记文件后刷新不再参与项目列表与同步。（纯发现测试通过）
- [ ] 旧单项目自动推送策略不被静默升级为自动拉取；新发现子项目默认仅手动，支持批量启用安全双向。
- [ ] Gradle test/build、模拟远端并发与失败测试、Windows/macOS 安装及双窗口重启验收完成并记录未执行项。
